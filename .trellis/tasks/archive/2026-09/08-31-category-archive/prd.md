# 分类归档功能

## Goal

为分类（categories）提供归档（archive）能力：让有历史时间记录的分类退出日常使用但完整保留数据；同时放宽删除约束——删除分类时其历史记录转为"未分类"而非被阻止或级联删除。

## Requirements

### 1. 数据模型

- `categories` 表新增 `archived_at TEXT` 列（NULL = 未归档，非 NULL = 归档时间 ISO 字符串）。
- 老库通过幂等迁移添加该列；新库直接建列。
- `time_entries.category_id` 改为可空（NULL = 未分类），配合删除放宽。

### 2. 归档 / 取消归档

- 归档某个父级分类时，其所有子分类一起归档（整体归档）。
- 归档子分类（单独归档一个 child）允许：仅归档该子分类，父级保持未归档。
- 取消归档：对已归档分类执行取消归档，级联恢复其归档祖先链（父级链向上全部取消归档）；不连带恢复归档的兄弟分类——只恢复目标分类及其祖先链，避免超出用户意图的操作。
- 归档 / 取消归档为幂等或返回当前状态均可，以实现简单、语义清晰为准。

### 3. 归档分类的可见性

- **新建时间记录时**（计时器、条目编辑器中的 CategoryPicker）：归档分类（含其子分类）从选择器中隐藏，不能选。
- 已存在的、指向归档分类的时间记录在编辑时：允许保持原分类不变（选择器显示当前值），若用户切换到其他分类则不能切回归档分类。
- **统计报表**：归档分类的时间记录正常计入统计，不做排除。
- 分类管理页：归档分类仍展示，但视觉上与活动分类区分（如置灰 + "已归档"标记），放在独立的折叠区域或列表尾部。

### 4. 删除约束放宽

- 删除分类不再要求"无时间记录、无 goal 引用"。
- 删除时：该分类（及其子分类）下的时间记录 `category_id` 置为 NULL（转为未分类）；引用该分类的 goals `category_id` 置为 NULL。
- 若正在运行的计时器（running entry）指向被删分类，同样置 NULL（计时器继续运行，显示为未分类）。
- "未分类"在 UI 上的呈现：时间轴/编辑器/统计中以现有缺省样式显示（如"未分类"文案），不额外建设未分类虚拟分类。

### 5. 其他约束

- 归档分类不能作为新分类的 parentId（创建/移动时校验）。
- 重名检查范围：归档分类与活动分类在同父级下共享命名空间（不因归档而允许重名）。

## Acceptance Criteria

- [ ] `GET /api/categories` 返回 `archivedAt` 字段（null 或 ISO 时间）。
- [ ] 归档父分类后，其子分类全部变为归档状态；单独归档子分类不影响父级。
- [ ] 归档/取消归档接口正确工作，取消归档会级联恢复归档父级链。
- [ ] CategoryPicker（计时器与条目编辑器）不再展示已归档分类。
- [ ] 统计报表中归档分类的时间记录仍正常计入。
- [ ] 删除一个有时间记录和 goal 引用的分类：操作成功，相关时间记录变为未分类（`category_id = NULL`），相关 goal 的 `category_id = NULL`，无孤儿外键错误。
- [ ] 分类管理页可执行归档/取消归档，归档分类有明确视觉区分。
- [ ] 老数据库升级路径无损（迁移幂等）。
- [ ] server 与 web 测试全部通过；新增行为有对应测试覆盖。

## Out of Scope

- 标签（tags）的归档功能。
- 未分类时间记录的批量重新归类工具。
- 归档分类的批量操作 / 搜索。
