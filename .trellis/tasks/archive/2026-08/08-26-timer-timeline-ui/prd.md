# 计时界面时间线改造

## 背景

当前计时页 (`TimerPage`) 下方用 `day-card` 列表展示当日记录（描述 · 分类标签 · 时间范围 · 时长逐行排列）。
用户希望将其改为类似 Toggl 的时间线视图，更直观地呈现一天内各条记录的时间分布与时长。

## 目标

将 `TimerPage` 当日记录区域从"逐行列表"改造为"纵向时间线"：

- 保留顶部计时控制条 (`timer-bar`) 不变。
- 下方以一天 0:00–24:00 为纵向时间轴，每条记录按起止时间定位、高度按时长比例、颜色取分类色。
- 参照 Toggl Calendar view 的核心视觉：纵向小时网格、彩色时间块、块内显示关键信息、当前时间指示线。

## 需求

### 功能需求

1. **全天纵向时间轴**：时间轴覆盖 0:00–24:00，以小时为主刻度显示时间标签。
2. **时间块定位**：每条当日记录渲染为一个色块，纵向位置 = 距 0:00 的偏移，高度 = 时长比例。色块颜色 = 该记录分类色（复用 `categoryColor`）。
3. **运行中条目**：当前正在计时的条目同样作为色块渲染，高度随 `nowMs` 实时增长，视觉上与已完成条目区分（如脉冲/边框）。
4. **块内信息**：当色块高度足够时，在块内显示描述 + 分类名 + 起止时间 + 时长；高度不足以显示全部时优先显示描述，其余信息通过悬浮提示查看。
5. **当前时间指示线**：在时间轴上绘制一条横线标记"现在"的位置，随时间移动。
6. **今日总计**：保留当日总时长的展示（时间线头部）。
7. **空状态**：当天无记录时显示空状态提示。

### 非功能需求

- 纯前端改造，不涉及后端 API 变更。复用现有 `api.todayEntries` 返回的 `dayStart`/`dayEnd`/`entries` 数据。
- 复用 `format.ts` 中的 `formatClock`、`formatDuration`、`categoryColor`、`clipSeconds`。
- 保持现有视觉风格（`styles.css` 变量体系），与 Toggl 的时间块布局理念一致但配色沿用项目既有主题。
- 无需引入新依赖。

### 不在本期范围

- 拖拽创建/编辑时间条目（Toggl 的 drag-to-create / resize / move）。
- 缩放控制。
- 周/多日视图切换。
- 点击色块打开编辑面板。
- 自动记录电脑活动（Toggl Timeline 的活动追踪功能）。

## 验收标准

1. 计时页下方显示一条覆盖 0:00–24:00 的纵向时间轴，每小时有刻度标签。
2. 当日每条记录渲染为色块，位置和高度与起止时间、时长比例一致。
3. 运行中条目实时增长，视觉上与已完成条目有区分。
4. 色块高度足够时块内可见描述、分类、时间、时长；高度不足时可悬浮查看。
5. 存在一条当前时间指示线，位置正确并随时间移动。
6. 当日总计在时间线头部展示。
7. 无记录时显示空状态。
8. 现有计时控制条行为不变（开始/停止/选分类/描述/已用时）。
9. `npm run build` 与 `npm test`（前端如有）通过，无类型错误。
