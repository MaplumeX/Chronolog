# Chronolog: Lyubishchev time tracker

## Goal

做一款可自托管的多用户时间追踪器：用 Docker 启动后，访客可公开注册；登录后用 Toggl 式开始/停止记时间；**每条记录必须属于一个分类**；在**统计页**看今天各类花了多久。

用户价值：一台实例给多人自助使用；开始追踪摩擦低；分类是第一公民，能按柳比歇夫的方式看「今天的时间去了哪一类」。未跟踪的时间保持空白，不要求填满 24 小时。

## Background

仓库 `Chronolog` 目前没有应用代码（README 仅标题）。Trellis 按 fullstack（backend + frontend）初始化，spec 仍是空脚手架。`00-bootstrap-guidelines` 与本产品无关。

用户原话：柳比歇夫时间管理法；参考 Toggl 的设计；希望是 Docker 应用。

已拍板的产品决策：

- 记录模型：Toggl 式选择性计时，不是完整日账本。
- 交付：Docker 自托管 Web，不是桌面客户端，也不是由我们运营的云 SaaS。
- 账号：多用户、记录隔离、公开注册、用户名 + 密码；第一版不做邮箱验证。
- 归类：每条必须有分类；不做 Toggl 式项目/标签。
- 第一版复盘：只有「今日分类合计」，放在**统计页**（对应 Toggl Reports），不放在计时页。事后补记、周/月报不做。
- 界面：学 Toggl 网页壳。左栏三项「计时 / 统计 / 分类」（已确认）。计时页只有顶栏 + 今日列表；今日分类合计只在统计页。
- 技术栈：Node.js 22 + Vite/React + Fastify + SQLite。用户不熟 Hono，后端不用 Hono。日后可接入 pi agent，本版不实现。

## Requirements

- R1. 已登录用户必须选择一个自己的分类，才可以开始计时；说明文字可选。
- R2. 已登录用户可以停止自己的当前计时；停止后生成一条带分类、可选说明、开始/结束时间与时长的记录。
- R3. 每个用户同一时刻最多一个正在运行的计时器。若开始新计时且已有一条在跑，先停止旧的再开始新的（Toggl 行为）。
- R4. 已登录用户能看到自己今天的时间条目列表，列表能看出每条的分类、说明与时长。正在运行的条目也要能看见（时长随时间增加）。
- R5. 未跟踪的时间不强制补记，界面也不把「填满一天」当作完成条件。
- R6. 用户能按仓库说明用 Docker Compose 启动本应用，再用浏览器访问。
- R7. 容器重启后，账号、分类与时间记录仍然存在。正在运行的计时器按原开始时间继续，不因关浏览器或重启而丢失。
- R8. 未登录不能开始/停止计时，也不能读取任何时间记录或分类。
- R9. 用户只能看到和操作自己的时间记录、计时器与分类。
- R10. 未登录访客可以用用户名和密码注册；用户名不可与已有账号重复。用户名 3–32 个字符（字母、数字、下划线）；密码至少 8 个字符。
- R11. 已注册用户可以用同一套用户名和密码登录，也可以登出。刷新页面后，未登出则仍保持登录。
- R12. 新账号预置默认分类：工作、学习、休息、事务。
- R13. 已登录用户可以新增分类、重命名自己的分类。分类名在该用户下不可重复，不能为空。
- R14. 分类下没有已停止记录、也没有正在使用它的计时器时，可以删除；否则删除必须被拒绝。
- R15. 已登录用户在**统计页**能看到「今天」各分类的合计时长。计时页不展示分类合计。没有记录的分类可以显示为 0 或不出现，但有记录的分类必须出现。「今天」按用户本地时区的日历日计算。
- R16. 界面语言为中文。

## Acceptance Criteria

- [ ] AC1. 未选分类时不能开始计时；选了分类后开始，界面显示该分类正在计时（R1）。
- [ ] AC2. 停止计时后，今天的列表中出现对应记录，含分类、时长与起止时间（R2、R4）。
- [ ] AC3. 已有计时在跑时再开始另一条：旧的变为已停止记录，新的成为唯一正在运行的计时，该用户不会有两条同时在跑（R3）。
- [ ] AC4. 一天只有部分时间被记录时，产品仍可用，不出现必须补齐 24 小时的流程（R5）。
- [ ] AC5. 按 README 用 `docker compose up` 启动后，浏览器能打开应用（R6）。
- [ ] AC6. 写入账号、分类和至少一条已停止记录后重启容器，账号仍可登录，分类与该记录仍在。重启前正在跑的计时，重启后仍在跑且开始时间不变（R7）。
- [ ] AC7. 未登录访问受保护页面或接口时，不能读到时间数据或分类，也不能创建计时（R8）。
- [ ] AC8. 用户 A 登录后看不到用户 B 的条目、分类或正在运行的计时（R9）。
- [ ] AC9. 访客可以注册；重复用户名、过短用户名或过短密码会被拒绝（R10）。
- [ ] AC10. 正确密码能登录；登出后不能再访问该用户的记录，直到再次登录。登录后刷新页面仍是登录状态（R11）。
- [ ] AC11. 新注册用户能看到默认分类：工作、学习、休息、事务（R12）。
- [ ] AC12. 用户可以新增分类并重命名；新分类可以用来开始计时。空名或与自己已有分类重名会被拒绝（R13）。
- [ ] AC13. 删除仍被记录或当前计时占用的分类会失败；删除未被占用的分类会成功（R14）。
- [ ] AC14. 今天在分类 A 记了两段、分类 B 记了一段后，打开统计页：A 的时长等于那两段之和，B 等于那一段（含仍在跑的计时截至查看时刻）。计时页上看不到这块合计（R15）。
- [ ] AC15. 主要界面文案为中文（R16）。

## Out of scope

- 强制填满 24 小时、日完整度、把空白当必须补记的缺口。
- 事后补记、编辑已停止条目的起止时间、删除已停止条目。
- 周报、月报、图表、日历视图。
- Toggl 式项目、标签（第二套归类维度）。
- 桌面客户端、浏览器插件、移动端原生 App。
- 由我们托管的多租户云服务。
- 管理员审批注册、邀请码、邮箱验证、第三方登录、密码重置邮件。
- 共享项目、团队工作区、成员协作、权限矩阵。
- 计费/账单、客户端、可计费费率、发票。
- 与日历/Slack 等第三方同步。
- 验证码、注册限流（记为后续加固，不阻塞第一版）。
- 接入 pi / LLM agent（后续任务；本版只把技术栈选成以后接得上的）。

## Risks

- 公开注册且无邮箱验证：实例若暴露在公网，任何人都能注册。第一版接受该风险。
- 「今天」依赖时区：Docker 容器默认常为 UTC；必须按用户本地日历日计算，否则中国用户会在早上 8 点前看到「昨天」。
