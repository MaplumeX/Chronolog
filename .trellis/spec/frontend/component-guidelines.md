# Component Guidelines

Light product shell, Tailwind v4 + shadcn/ui (new-york), Linear-style **light card** system (task 08-31-layout-visual-hierarchy). Content modules live on a shared light card primitive (`ui/card`): hairline border + faint `shadow-xs` + uniform `rounded-lg`. Keep it *light* — no large shadows, no high-contrast elevated cards, no per-page radius drift. Page structure is a three-tier hierarchy: Shell top-bar page title → page-top toolbar row (filters left, primary action `ml-auto` right) → content module Cards (`space-y-6` apart).

Tokens live on `:root` and `.dark` in `web/src/styles.css` (shadcn CSS variables, teal cool-theme, both light and dark maintained — see [Design Tokens](./design-tokens.md)). Theme switching is handled by `ThemeSwitcher` + the `use-theme` hook; do not hardcode raw colors in components.

## Shell

`Shell` (`web/src/components/Shell.tsx`): `SidebarProvider` + `Sidebar collapsible="icon"` + `SidebarInset`.

- Top bar (`min-h-12`, `border-b`): `[SidebarTrigger][header]`. `Shell` accepts a `header?: ReactNode` prop; `App` is the sole assembler — non-timer pages pass a page-level `<h1>` (`px-2 text-xl font-semibold tracking-tight`, `nav.*` i18n key) and the pages themselves have no `<h1>`; the timer page passes `<TimerBar {...timer.barProps} />` (Toggl-style: the timer bar lives in the top bar). The sidebar nav group carries a `SidebarGroupLabel` (`nav.group` key, uppercase tracking-wide).
- Desktop: expand to labels, collapse to icon rail. `SidebarTrigger` in the inset header only (not a second nav).
- Narrow (`<768px`, task 09-08-mobile-responsive): a dedicated lightweight tree replaces the sidebar entirely — top bar (`header` prop content + a `Settings`-icon button top-right, hit area extended via `after:-inset-1.5`) + fixed bottom tab bar (`MobileTabBar`, `fixed inset-x-0 bottom-0 z-40 md:hidden`, `bg-card` + `border-t`, `pb-[env(safe-area-inset-bottom)]`). Five tabs (timer/stats/goals/categories/tags, `aria-current="page"` + `text-primary` active, `min-h-[48px]` hit areas); settings is NOT a tab. Content area gets `pb-[calc(5rem+env(safe-area-inset-bottom))]` so the tab bar never covers content (`8.5rem` on the timer page — the `MobileTimerDock` capsule sits above the tab bar, task 09-10-mobile-timer-dock). Nav constants live in `nav-items.ts` (`NAV_ITEMS` + `PageId`); desktop sidebar and the mobile tab bar both consume it. The Sidebar Sheet drawer is desktop-only now (in practice never rendered — `useIsMobile()` gates the whole sidebar tree).
- Mobile timer dock (task 09-10-mobile-timer-dock): on the timer page the mobile header does NOT render the `TimerBar` — `Shell`'s mobile branch replaces `props.header` with the `t("nav.timer")` page title (all pages share the same header shape; the desktop branch still renders the `header` prop `TimerBar` unchanged, and `App`'s header assembly is untouched — the substitution is Shell-internal). Instead, `Shell` takes a `mobileTimerDock?: ReactNode` slot (assembled by `App` from `<MobileTimerDock {...timer.barProps} />`, rendered after `MobileTabBar`; ignored on desktop). `MobileTimerDock` (`web/src/components/MobileTimerDock.tsx`) is a pure presentational component (no `api` import) whose props mirror `TimerBar` plus `categoryColor: string | null` (a derived field added to `barProps`: `running ?? selected` category color, null = no category; uncolored dot is not rendered). Capsule row: `fixed inset-x-0 bottom-[calc(var(--mobile-tabbar-h)+env(safe-area-inset-bottom))] z-40` (`--mobile-tabbar-h: 48px` token in `styles.css`), `bg-card border-t` (same material as the tab bar, no floating shadow), `min-h-14`; content = category dot + description `truncate` (placeholder when empty) + elapsed `font-mono tabular-nums` as the `SheetTrigger` (sibling of, not nested inside, the round play/stop button — buttons cannot nest). Play/stop button reuses the `TimerBar` spec (`size-11 rounded-full`, default/destructive, `stopPropagation` so clicking it never opens the sheet). The bottom sheet (direct `ui/sheet`, NOT `ResponsiveEditPopover` — that one serves anchored popovers with desktop pass-through; this is a fixed dock) follows the #51 spec: `side="bottom"`, drag-handle, `max-h-[85dvh]` inner scroll, safe-area padding, sr-only `SheetTitle`, `showCloseButton={false}`, no play/stop button inside (the capsule button owns it). Closing the sheet never affects timing state.
- Variant is default `sidebar`, not `floating` / `inset` (those visually detach the sidebar from the shell frame).
- Unauthenticated users see only `AuthPage`. No shell.

## Page container & cards

`PageContainer` (`web/src/components/PageContainer.tsx`): the single centered, width-capped wrapper for page content — `mx-auto w-full p-4 md:p-6` plus a `size` prop with three tiers: `default` (`max-w-3xl`, forms/settings), `wide` (`max-w-5xl`, data/table/stats pages), `full` (`max-w-none`, no cap). Every shell page wraps its content in one (Stats/Goals/Categories/Tags = `wide`, Settings = `default`) so wide screens get centered content with side whitespace instead of unbounded stretch. Two exceptions: the timer page's `Timeline` takes no container (horizontal scrolling needs full width), and `AuthPage` keeps its own centered `max-w-sm`.

`ui/card` (`web/src/components/ui/card.tsx`): the single source of card styling — six pieces (`Card` / `CardHeader` / `CardTitle` / `CardDescription` / `CardContent` / `CardFooter`), same `cn()` + `data-slot` shape as the other `ui/*` primitives. `Card` = `rounded-lg border bg-card text-card-foreground shadow-xs`; `CardTitle` = `text-sm font-semibold` (module-container title, not a hero-card headline); default padding is the compact `p-4` family (`CardHeader`/`CardContent`/`CardFooter`), with `p-6` reserved for airy spots (big-number summaries, standalone forms). Page structure convention: a toolbar row first (`flex items-center gap-2`, filters left, primary action `ml-auto` right), then module cards spaced `space-y-6`.

Table-in-card pattern (Goals / Tokens): `Card className="overflow-hidden"` + `CardContent className="p-0"` wrapping the `Table` directly — the header row aligns with the card's top edge, row dividers come from the table, and `overflow-hidden` clips the corners to `rounded-lg`. Categories / Tags used this pattern until task 08-31-redesign-categories-tags replaced their tables with the shared tree-list card below (same card skeleton: `Card overflow-hidden` + `CardContent p-0`, `divide-y` rows, no table header).

- `Timeline` — 0:00–24:00 ruler; one colored block per entry; running entry grows with `nowMs`; now-line; cross-day rendering contract (task 08-31-cross-day-entry-display): block geometry is clipped to the column window `[dayStart, dayEnd)` via `clipRangeMs` before computing `top`/`heightPct` — never position a block from raw `startedAt`/`stoppedAt` (an entry started the previous night would overdraw from 0:00 with its full length); the duration shown on the block and in its tooltip is the whole-entry `e.durationSeconds` (running counts to `nowMs`), NOT the day-clipped slice — the day-clipped `clipSeconds` value is reserved for the per-day column-header totals only; the on-block and tooltip time range uses `formatEntryTimeRange` (shared with `title`): a non-cross-day entry shows `HH:MM – HH:MM`; a cross-day entry shows **both** endpoints with a full `MM-DD` date — `MM-DD HH:MM – MM-DD HH:MM` (including the endpoint that falls on today; no `昨天/明天` relative words). Cross-day is decided by comparing the tz calendar-day ordinals of start vs end (running entries compare start vs `nowMs`; their right end stays `…`). Day ordinals come from tz calendar labels via `Intl.DateTimeFormat("en-CA", { timeZone: tz })`, DST-safe, never UTC-ms subtraction; full/compact/mini tiers; day grand total in the header. Scale density is switchable: `SCALES = [60, 30, 15, 5]` minutes (default 60), toggled by −/+ buttons next to the day/week Tabs (boundary buttons disabled). Geometry contract: each tick is a fixed 40px tall (`PX_PER_TICK`), so the timeline height is `(1440 / scale) × 40px` (60→960px, 5→11520px) set as an inline style on `.timeline-inner` — do NOT restore a fixed height in CSS. All tick labels render (HH:MM, 12px). Block tier thresholds are pixel-based (≥24px full / ≥10px compact / else mini), not percent-based, so they stay correct across scales. Scroll-anchoring re-runs when `scale` changes. i18n keys: `timeline.zoomIn` (+) / `timeline.zoomOut` (−), with no visible scale label between the buttons. Supports `mode: "day" | "week"`: day renders one column (today), week renders 7 side-by-side day columns (Mon–Sun, horizontal scroll) with a week-range header, per-day column headers (bold day number + weekday + day total, today's header highlighted with `bg-primary/10` + `text-primary`), and the now-line only in today's column. Single-day rendering is shared via an internal `DayColumn` component (`showRuler?: boolean` — week mode renders one shared ruler on the left and passes `showRuler={false}` so hour labels appear once and grid lines span all days; empty days show no hint in week mode). Stopped blocks are clickable and open an edit popover (`EntryEditor`); running blocks have no `onClick`. The popover is anchored to the block via `Popover.Anchor` (Root lives at `Timeline` top level, Anchor inside `DayColumn`); `EntryEditor` gets `key={entry.id}` so switching entries remounts the form. Drag-to-create on empty track space (task 08-27-timeline-drag-create): `DayColumn` takes optional `onDragCreate({ startedAt, stoppedAt })`; when absent, no pointer handlers attach and behavior is unchanged. pointerdown on the track ignores presses that hit `.timeline-block` (`closest()` check) so block click-edit is unaffected; `setPointerCapture` + pointermove render a `.timeline-block.drag-preview` (semi-transparent, `HH:MM – HH:MM` via `formatClock`, `pointer-events: none`) and pointerup with no snap movement cancels (plain click never creates). Clicking a slot sets the existing draft state with the gap's full global start/end (crossing midnight is fine) and opens the same draft popover / `EntryEditor`; the PopoverAnchor is pinned inside the clicked slot (it stays rendered while the gap data is unchanged). When `boundary` is null (request failed / not loaded) only in-column gaps render — degraded, harmless. ## CSS Cascade Layers gotcha

Un-layered CSS beats Tailwind v4 `@layer utilities` classes regardless of source order. Do not set `cursor: default` on a base class that also gets `cursor-pointer` from a utility — the base wins and the pointer never shows. Scope the base rule to the non-interactive state instead (e.g. `.timeline-block.running { cursor: default }`).

## Dialog animation gotcha (no zoom on large dialogs)

`DialogContent` (`web/src/components/ui/dialog.tsx`) animates with **fade only** — `zoom-in-95`/`zoom-out-95` were removed deliberately (task 08-30-goal-feature, GoalEditorDialog lag). The tw-animate-css `enter`/`exit` keyframes combine `scale3d` + `filter` interpolation per frame; on a large, tall, scrollable dialog (`max-h-[90dvh] overflow-y-auto`, emoji grid + form) the whole content re-rasterizes as a compositing layer every frame, so both open and close jank. Small dialogs (Settings delete confirm) never showed it — the cost scales with dialog area. Do not re-add zoom utilities to DialogContent or any large dialog/popover; opacity-only animation stays on the GPU compositor. If a dialog still janks, the next suspect is the full-screen overlay compositing, not JS.

`StatsPage` (task 09-09-redesign-stats-views, full rewrite in `web/src/pages/stats/`) is **view-driven**, not range-preset-driven. Product premise: Lyubishchev-style time tracking — the user is assumed to log all 24h, so **totals are near-constant and "volume" metrics are meaningless** (no total row, no total delta, no active-days, no avg-per-day totals; only per-category structure, coverage, and per-category deltas). Four views (Tabs `stats.view.*`, default day, not persisted):

- **Architecture**: `web/src/pages/stats/StatsPage.tsx` is the container (view Tabs, tag filter `ml-auto`, query-window computation, `api.statsRange` fetching with a `Map<cacheKey, RangeStats>` cache keyed `from|to|tagId|rollup`, prev-period second request for week/month, `seqRef` race guard — stale async results are dropped). Sub-views: `DayView` (24h ring + hourly stacked bars + composition list), `WeekView` (7 normalized stacked columns + per-category vs-last-week list), `MonthView` (category-selectable calendar heatmap + discipline KPIs), `CustomView` (range selector + stacked trend + category/tag distribution). Shared: `StackedCompositionChart.tsx` (normalized stacked columns — week and custom MUST render identically), `stats-utils.ts` (pure functions + DST-safe tz math, fully unit-tested), `DayRingChart.tsx`, `now.ts` (`useNowMs` drives today's running-entry growth).
- **Unlogged bucket**: window seconds − covered seconds (running entries clip at `nowMs`), rendered as a gray segment in every chart and a row in every composition list (`stats.unlogged`); under tag filtering it naturally means "time not covered by that tag's entries". DayView uses `/api/entries/today?date=&tagId=` (`listToday` supports both; no rollup param — DayView merges children into parents client-side via `tools.categories` parentId) while week/month/custom use `statsRange` (which now returns `entries: EntryDto[]`, task 09-09).
- **DayView**: recharts `PieChart` ring with `startAngle={90} endAngle={-270}` (recharts polar angles are mathematical/CCW-positive, so visual clockwise = decreasing angle; 0:00 at top). `buildRingSegments` unions coverage intervals, merges adjacent same-category segments, inserts unlogged gray arcs. Center overlay shows coverage (`h:mm:ss / 24h`). Hourly distribution = 24 stacked buckets via `hourlyByCategory` (DST-safe: bucket widths may ≠ 3600s; day window may be 23h/25h).
- **WeekView/MonthView deltas**: per-category only (`deltaPercent`, previous=0 → null → renders `—`), `▲` `text-primary` / `▼` `text-destructive`. No total row ever.

## Anti-patterns

- Do not put category totals on the timer page.
- Do not add React Router; page state is `PageId` in `App`.
- Do not stop the timer on `beforeunload` — R7 says the timer survives browser close.
- `ui/card` is the single source of card styling — do not hand-assemble `border` + `rounded-*` + `shadow-*` on page-level divs.
- Keep cards light: no large shadows, no high-contrast elevated/floating cards, radius stays `rounded-lg`.
- Do not add a page-level `<h1>` — page titles render in the Shell top bar via the `header` prop.
- Do not mix another icon set or CSS framework on top of Tailwind + shadcn.

## Mobile adaptation (task 09-08-mobile-responsive)

Two breakpoint dimensions, each used where it is the right tool:

- **Width breakpoint (`useIsMobile()`, <768px)** — structural/layout decisions: Shell navigation form, week-view column geometry, timeline ruler width (`.timeline-ruler` 56→44px, `.timeline-track` `left` synced via `:not(.timeline-track--full)` so week columns' full-bleed tracks stay at `left: 0`).
- **Capability breakpoint (`@media (hover: none)`, styles.css)** — input-affordance decisions: `.touch-hit` (hit-area expansion via `::after inset: -8px`, visual size unchanged, ≥40px targets) and `.touch-always-visible` (hover-reveal row actions become always-visible; unlayered CSS beats Tailwind utilities). A width breakpoint cannot cover "wide touchscreen" or "narrow window + mouse"; use the capability query for anything hover-dependent.

Touch-specific contracts:

- Timeline drag-to-create is desktop-only: `Timeline` passes `onDragCreate={isMobile ? undefined : ...}`; `DayColumn`'s existing `if (!onDragCreate) return` guards short-circuit the pointer handlers. Gap-slot tap is the sole mobile create path — never remove it.
- Week view scrolls horizontally: header row + columns row share one width (`w-max min-w-full` wrapper, both rows `w-full`) so alignment holds by construction; ruler spacer is `w-11 md:w-14` synced to the CSS 44/56px.
- `PopoverContent` (`ui/popover.tsx`) has a global `max-w-[calc(100vw-1rem)]` clamp — do not add per-caller viewport-width overrides.
- Goals/Tokens tables scroll inside `ui/table`'s own `table-container`; the outer `Card` stays `overflow-hidden` (corner clipping).
- `SettingsPage` `TabsList` uses `max-w-full overflow-x-auto` (`auto` shows no scrollbar when not overflowing).

**Gotcha — empty absolutely-positioned pseudo-elements collapse to zero width.** A `::after` with only `top`/`bottom` set (no `left`/`right`/`width`) shrinks to fit content = 0px wide, silently killing the hit area. The `.touch-hit--x` base rule must declare `left: 0; right: 0` for the `:first-child`/`:last-child` single-side (`-8px`) overrides to work. Adjacent small buttons (`gap-1`) must use directional expansion — full-perimeter `.touch-hit` on neighbors overlaps by (16px − gap) and the later sibling's pseudo-element wins.

## Mobile editing sheets (task 09-09-mobile-editing-sheet)

All editing popovers become bottom sheets on mobile via the shared container `ResponsiveEditPopover` (`web/src/components/ResponsiveEditPopover.tsx`, pure container — no `api` import, no business logic). Callers: `Timeline` (single instance for all three `EntryEditor` entries — edit / drag-draft / gap-draft, plus `rootChildren` carrying the timeline body) and `HierarchicalListCard` (addChild / edit forms, `anchor` = the RectSnapshot virtualRef).

Contract: `{ open, onOpenChange, anchor?: RefObject<HTMLElement | null>, side? (default "bottom" — matches Radix PopoverContent's native default, so callers that previously omitted `side` keep their original placement; Timeline passes "right"), align?, sideOffset?, contentClassName? (width class like "w-80"/"w-72"), onFocusOutside? (structural `{ target, preventDefault }` signature — the 300ms focus-guard passes through untouched), srTitle, children (popover/sheet content), rootChildren? (page body) }`.

- Desktop (`!isMobile`): transparent pass-through of `Popover + PopoverAnchor(virtualRef) + PopoverContent` — equivalent DOM/behavior to the previous direct usage; `onFocusOutside` grace window still applies.
- Mobile (`isMobile`): `Sheet + SheetContent side="bottom"` — full-width, `max-h-[85dvh] overflow-y-auto` inner scroll, `pb-[env(safe-area-inset-bottom)]`, non-interactive drag-handle bar, sr-only `SheetTitle` (Radix a11y), `showCloseButton={false}` (forms carry their own cancel). z-50 overlay covers `MobileTabBar` (z-40) by construction. `anchor`/`side`/`align`/`sideOffset`/`contentClassName`/`onFocusOutside` are ignored on mobile (Sheet is modal; Radix Dialog manages focus).
- **`rootChildren` gotcha**: Radix `PopoverAnchor` without a Popover Root **throws** (`must be used within "Popover"`) — it does NOT degrade silently. Timeline's body contains zero-size anchors (selected card) and RectSnapshot virtualRef anchors (gap rows), so the container renders `rootChildren` inside the desktop Popover Root (context only, no DOM) and inside an `open={false}` empty Popover Root on mobile (context only, closed Root has no side effects). Callers whose anchors are purely external virtualRefs (`HierarchicalListCard`) pass `anchor` instead and skip `rootChildren`.

`EntryEditor` mobile button layout (deliberate, task 09-09): title row `justify-between` (title left, destructive delete as `min-h-12` ghost text-link right — NOT the desktop `mr-auto` row slot), then secondary row (merge prev/next, ghost `min-h-12 flex-1`), then primary row (cancel/save `h-12 flex-1` each). Draft mode renders only the primary row. Desktop keeps the original single `flex-wrap justify-end` row — state/callbacks/disabled logic are shared, only the button-area JSX branches. `MergeDialog` `DialogContent` carries `max-h-[90dvh] overflow-y-auto` for narrow screens.

Known acceptable mobile cosmetic: after save/cancel the sheet content empties during the ~300ms exit animation (entry state is cleared immediately) — do not "fix" by retaining stale form state.
