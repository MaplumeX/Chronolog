# Component Guidelines

Light product shell, Tailwind v4 + shadcn/ui (new-york), Linear-style **light card** system (task 08-31-layout-visual-hierarchy). Content modules live on a shared light card primitive (`ui/card`): hairline border + faint `shadow-xs` + uniform `rounded-lg`. Keep it *light* — no large shadows, no high-contrast elevated cards, no per-page radius drift. Page structure is a three-tier hierarchy: Shell top-bar page title → page-top toolbar row (filters left, primary action `ml-auto` right) → content module Cards (`space-y-6` apart).

Tokens live on `:root` and `.dark` in `web/src/styles.css` (shadcn CSS variables, teal cool-theme, both light and dark maintained — see [Design Tokens](./design-tokens.md)). Theme switching is handled by `ThemeSwitcher` + the `use-theme` hook; do not hardcode raw colors in components.

## Shell

`Shell` (`web/src/components/Shell.tsx`): `SidebarProvider` + `Sidebar collapsible="icon"` + `SidebarInset`.

- Top bar (`min-h-12`, `border-b`): `[SidebarTrigger][header]`. `Shell` accepts a `header?: ReactNode` prop; `App` is the sole assembler — non-timer pages pass a page-level `<h1>` (`px-2 text-xl font-semibold tracking-tight`, `nav.*` i18n key) and the pages themselves have no `<h1>`; the timer page passes `<TimerBar {...timer.barProps} />` (Toggl-style: the timer bar lives in the top bar). The sidebar nav group carries a `SidebarGroupLabel` (`nav.group` key, uppercase tracking-wide).
- Desktop: expand to labels, collapse to icon rail. `SidebarTrigger` in the inset header only (not a second nav).
- Narrow (`<768px`): same items in the Sidebar Sheet drawer. Opening a page closes the drawer (`setOpenMobile(false)`).
- Variant is default `sidebar`, not `floating` / `inset` (those visually detach the sidebar from the shell frame).
- Unauthenticated users see only `AuthPage`. No shell.

Nav items (fixed product IA):

| `PageId` | Label | Main |
|----------|--------|------|
| `timer` | 计时 | Timer bar (in the Shell top bar via `header`) + today’s entry timeline |
| `stats` | 统计 | Range stats (today/week/month/custom) — trend chart + category share + tag breakdown (task 08-29-refactor-stats-page) |
| `goals` | 目标 | Goal list + progress (`GoalsPage`, task 08-30-goal-feature) — lucide `Target` icon, placed after 统计 |
| `categories` | 分类 | Category tree list (`HierarchicalListCard`) |
| `tags` | 标签 | Tag tree list (create / rename / delete, same shared component) |
| `settings` | 设置 | Tabbed settings — 通用 / 账户 / API Tokens (task 08-29-tabbed-settings) |

Footer: two items — a non-interactive user display (`displayName ?? username`, `pointer-events-none` + `tabIndex={-1}`, first-letter avatar in icon mode) and a separate `Settings`-icon entry (lucide `Settings` + `nav.settings`, clickable → settings page, closes the mobile drawer). Language switcher, theme switcher, logout, and API tokens live in the tabbed settings page — do not re-add them to the sidebar. While a timer runs, the 计时 item shows elapsed (`formatDuration`) via `SidebarMenuBadge`. Do not add Calendar, Timesheet, week pickers, or a marketing landing page.

Screen-reader copy on Sidebar/Sheet is i18n-ized (`sidebar.nav`, `sidebar.toggle`, `sidebar.close` keys).

## Page container & cards

`PageContainer` (`web/src/components/PageContainer.tsx`): the single centered, width-capped wrapper for page content — `mx-auto w-full p-4 md:p-6` plus a `size` prop with three tiers: `default` (`max-w-3xl`, forms/settings), `wide` (`max-w-5xl`, data/table/stats pages), `full` (`max-w-none`, no cap). Every shell page wraps its content in one (Stats/Goals/Categories/Tags = `wide`, Settings = `default`) so wide screens get centered content with side whitespace instead of unbounded stretch. Two exceptions: the timer page's `Timeline` takes no container (horizontal scrolling needs full width), and `AuthPage` keeps its own centered `max-w-sm`.

`ui/card` (`web/src/components/ui/card.tsx`): the single source of card styling — six pieces (`Card` / `CardHeader` / `CardTitle` / `CardDescription` / `CardContent` / `CardFooter`), same `cn()` + `data-slot` shape as the other `ui/*` primitives. `Card` = `rounded-lg border bg-card text-card-foreground shadow-xs`; `CardTitle` = `text-sm font-semibold` (module-container title, not a hero-card headline); default padding is the compact `p-4` family (`CardHeader`/`CardContent`/`CardFooter`), with `p-6` reserved for airy spots (big-number summaries, standalone forms). Page structure convention: a toolbar row first (`flex items-center gap-2`, filters left, primary action `ml-auto` right), then module cards spaced `space-y-6`.

Table-in-card pattern (Goals / Tokens): `Card className="overflow-hidden"` + `CardContent className="p-0"` wrapping the `Table` directly — the header row aligns with the card's top edge, row dividers come from the table, and `overflow-hidden` clips the corners to `rounded-lg`. Categories / Tags used this pattern until task 08-31-redesign-categories-tags replaced their tables with the shared tree-list card below (same card skeleton: `Card overflow-hidden` + `CardContent p-0`, `divide-y` rows, no table header).

## Pages

`AuthPage`: centered `max-w-sm` form on `bg-background`, `Tabs` for 登录/注册, the form wrapped in a light `Card` (`CardContent p-6`). Loads `GET /api/meta` on mount (failure = treat as open); when `registrationOpen` is false the 注册 tab is disabled with `auth.registrationClosed` copy.

`SettingsPage` (task 08-29-tabbed-settings): shadcn `Tabs` with three tabs — 通用 (language via `LanguageSwitcher` + theme via `ThemeSwitcher`, one `Label`-annotated row each), 账户 (profile / change password / logout / danger zone), API Tokens (embeds `TokensPage`). Wrapped in `PageContainer` `default`; each tab's form groups are light cards — 通用 one card (language + theme rows), 账户 three cards (profile / change password / danger zone with `border-destructive/30` + destructive title, `space-y-6` between them), tokens tab renders `TokensPage` whose table follows the table-in-card pattern. Tab state is SettingsPage-local; default tab is 账户. `TabsList` keeps `max-w-md` only — no `overflow-x-auto` (it renders a permanent scrollbar on desktop; the three short tabs never overflow). 账户 tab content: profile (username + displayName, save disabled until something changed), change password (3 password inputs, submit blocked on mismatch), logout button, danger zone (delete account via shadcn `Dialog` password confirmation). Props `{ user, onUserUpdated, onLoggedOut, themeMode, onThemeMode, onLogout }`; after `DELETE /api/account` succeeds, `App` just clears local state (server already cleared the cookie — calling `api.logout` would 401). No `<h1>`; page title renders through the Shell `header` like other non-timer pages. `LanguageSwitcher`/`ThemeSwitcher` render plain `Button` triggers with `DropdownMenu` — they must not depend on sidebar primitives.

Timer orchestration lives in the `useTimerController` hook (see [Hook Guidelines](./hook-guidelines.md)) — there is no `TimerPage`. Markup lives in:

- `TimerBar` — rendered inside the Shell top bar (Toggl "What are you working on?" style): `text-lg` input filling the row, `rounded-lg` outlined pickers, mono `text-xl` elapsed, round solid play/stop (`aria-label` 开始 / 停止). No outer `border-b` (the header has one). Stacks vertically below `md`. While running, the input / category / tag pickers stay editable (task 08-30-edit-while-timing): description is a local draft saved via a 600ms debounce, category/tag changes save immediately — both call `PATCH /api/timer/current` and overwrite the global `current` entry with the server response; stopping cancels any pending debounce so a stale update never hits the 409 path.
- `CategoryPicker` — shadcn `DropdownMenu`.
- `Timeline` — 0:00–24:00 ruler; one colored block per entry; running entry grows with `nowMs`; now-line; cross-day rendering contract (task 08-31-cross-day-entry-display): block geometry is clipped to the column window `[dayStart, dayEnd)` via `clipRangeMs` before computing `top`/`heightPct` — never position a block from raw `startedAt`/`stoppedAt` (an entry started the previous night would overdraw from 0:00 with its full length); the duration shown on the block and in its tooltip is the whole-entry `e.durationSeconds` (running counts to `nowMs`), NOT the day-clipped slice — the day-clipped `clipSeconds` value is reserved for the per-day column-header totals only; the on-block and tooltip time range uses `formatEntryTimeRange` (shared with `title`): a non-cross-day entry shows `HH:MM – HH:MM`; a cross-day entry shows **both** endpoints with a full `MM-DD` date — `MM-DD HH:MM – MM-DD HH:MM` (including the endpoint that falls on today; no `昨天/明天` relative words). Cross-day is decided by comparing the tz calendar-day ordinals of start vs end (running entries compare start vs `nowMs`; their right end stays `…`). Day ordinals come from tz calendar labels via `Intl.DateTimeFormat("en-CA", { timeZone: tz })`, DST-safe, never UTC-ms subtraction; full/compact/mini tiers; day grand total in the header. Scale density is switchable: `SCALES = [60, 30, 15, 5]` minutes (default 60), toggled by −/+ buttons next to the day/week Tabs (boundary buttons disabled). Geometry contract: each tick is a fixed 40px tall (`PX_PER_TICK`), so the timeline height is `(1440 / scale) × 40px` (60→960px, 5→11520px) set as an inline style on `.timeline-inner` — do NOT restore a fixed height in CSS. All tick labels render (HH:MM, 12px). Block tier thresholds are pixel-based (≥24px full / ≥10px compact / else mini), not percent-based, so they stay correct across scales. Scroll-anchoring re-runs when `scale` changes. i18n keys: `timeline.zoomIn` (+) / `timeline.zoomOut` (−), with no visible scale label between the buttons. Supports `mode: "day" | "week"`: day renders one column (today), week renders 7 side-by-side day columns (Mon–Sun, horizontal scroll) with a week-range header, per-day column headers (bold day number + weekday + day total, today's header highlighted with `bg-primary/10` + `text-primary`), and the now-line only in today's column. Single-day rendering is shared via an internal `DayColumn` component (`showRuler?: boolean` — week mode renders one shared ruler on the left and passes `showRuler={false}` so hour labels appear once and grid lines span all days; empty days show no hint in week mode). Stopped blocks are clickable and open an edit popover (`EntryEditor`); running blocks have no `onClick`. The popover is anchored to the block via `Popover.Anchor` (Root lives at `Timeline` top level, Anchor inside `DayColumn`); `EntryEditor` gets `key={entry.id}` so switching entries remounts the form. Drag-to-create on empty track space (task 08-27-timeline-drag-create): `DayColumn` takes optional `onDragCreate({ startedAt, stoppedAt })`; when absent, no pointer handlers attach and behavior is unchanged. pointerdown on the track ignores presses that hit `.timeline-block` (`closest()` check) so block click-edit is unaffected; `setPointerCapture` + pointermove render a `.timeline-block.drag-preview` (semi-transparent, `HH:MM – HH:MM` via `formatClock`, `pointer-events: none`) and pointerup with no snap movement cancels (plain click never creates). Snap map `{60: 15, 30: 10, 15: 5, 5: 1}` minutes (`Math.round`), and equal snapped start/end becomes one grid step (min-duration rule). Draft state lives in `Timeline` as `{ dayStart, startedAt, stoppedAt }` — week mode passes the dragged column's `dayStart` so the entry lands on that day — and opens the same Popover with `EntryEditor` in draft mode; save calls `api.createEntry` then refreshes, cancel/close/`pointercancel` discard the draft. Also handle `onPointerCancel` to avoid a stale preview when the OS interrupts the drag. Gap placeholder slots (task 08-29-gap-placeholder-slots): `Timeline` takes an optional `boundary` prop (`BoundaryEntries \| null` — adjacent entries just outside the view window, from `api.boundaryEntries`); it computes global gaps (`Gap = { startMs, endMs }`, absolute instants that may span days) as the spaces between coverage intervals of all view entries (running right edge = `nowMs`) plus the boundary neighbors, then per `DayColumn` renders only the intersection with that column's window as statically-visible `.timeline-slot` divs (dashed border via `--muted-foreground` color-mix + translucent `--muted` fill, token-only colors). A visible segment shorter than `MIN_SLOT_PX` (10px) is not rendered; pointerdown on the track also early-returns for `.timeline-slot` (closest check) so clicking a slot never starts a drag preview. Clicking a slot sets the existing draft state with the gap's full global start/end (crossing midnight is fine) and opens the same draft popover / `EntryEditor`; the PopoverAnchor is pinned inside the clicked slot (it stays rendered while the gap data is unchanged). When `boundary` is null (request failed / not loaded) only in-column gaps render — degraded, harmless.

The timer page must **not** show a per-category breakdown. That is `StatsPage` only (R15).

`TagPicker` — shadcn `DropdownMenu` multi-select; checked items show a `Check` icon and `bg-accent`. `TimerBar` renders it as a slot. While running with tags selected, read-only tag badges replace the picker; running tag edits go through `use-timer-controller`'s immediate `PATCH /api/timer/current` path (the picker still shows when the running entry has no tags).

`DateTimePicker` (`web/src/components/DateTimePicker.tsx`, task 08-29-beautify-time-picker): replaces native `datetime-local` in `EntryEditor` for start/end times. Controlled component with value contract `"YYYY-MM-DDTHH:mm:ss"` local-time string (same as the old `toLocalInput` output) — never change this format. Trigger is an outline `Button` (`rounded-lg w-full justify-start`, `CalendarClock` icon, localized date + mono `tabular-nums` time), styled to match the other pickers. Popover content: `ui/calendar` (locale `zhCN`/`enUS` via `i18n.language`, same as `DateNav`; selecting a date keeps the time part, popover stays open; month is local state synced from the value's date so prev/next navigation works) + a single native `<input type="time" step={1}>` (`ui/input` Input, `border-t` separator) + a "Now" shortcut (`entry.now`). The time input's value is the `HH:mm:ss` tail of the value contract, rejoined with the date part on change; an empty (cleared) input never commits (current value kept), all other values are browser-guaranteed valid `HH:mm:ss`. Segment editing/stepping is the browser's native behavior — no custom keyboard contract. `color-scheme` adapts the picker indicator and segments to both themes (light / `.dark`); semantic tokens only; no new dependencies.

`Timeline` full tier shows a tag badge row (dot + name, `categoryColor(tag.name)`) under `block-meta`; compact/mini tiers skip badges, tooltip title appends tag names.

`EntryEditor` (popover content): description / category / tags / start+end time (`DateTimePicker`, see below, keeps seconds) / live duration / save / cancel. Time conversion is browser-local (`new Date(value).toISOString()`), matching `TimerBar`. Props are either `entry: TimeEntry` (edit, calls `api.updateEntry`) or `draft: { startedAt, stoppedAt }` (create, calls `api.createEntry`, empty title `entry.create`, categoryId starts `""` and the save button is disabled until a category is picked). Refresh today+week only (never resets the start-timer form) and close the popover; 409 `OVERLAP` shows `entry.overlap` copy in both modes. Edit mode also shows a delete button on the left of the button row (`mr-auto` ghost + `text-destructive`, task 08-31-delete-dialog-confirm): clicking it opens the shared `ConfirmDialog` (see below), confirm runs `api.deleteEntry` then reuses `onSaved()` (close popover + refresh today/week); failure closes the dialog but keeps the error copy in the editor (retryable); an independent `deleting` state disables the dialog buttons and all three editor buttons while in flight; draft mode never renders it. Running entries are rejected server-side with 409 — the editor surfaces the `ApiError.message` copy.

## CSS Cascade Layers gotcha

Un-layered CSS beats Tailwind v4 `@layer utilities` classes regardless of source order. Do not set `cursor: default` on a base class that also gets `cursor-pointer` from a utility — the base wins and the pointer never shows. Scope the base rule to the non-interactive state instead (e.g. `.timeline-block.running { cursor: default }`).

## Dialog animation gotcha (no zoom on large dialogs)

`DialogContent` (`web/src/components/ui/dialog.tsx`) animates with **fade only** — `zoom-in-95`/`zoom-out-95` were removed deliberately (task 08-30-goal-feature, GoalEditorDialog lag). The tw-animate-css `enter`/`exit` keyframes combine `scale3d` + `filter` interpolation per frame; on a large, tall, scrollable dialog (`max-h-[90dvh] overflow-y-auto`, emoji grid + form) the whole content re-rasterizes as a compositing layer every frame, so both open and close jank. Small dialogs (Settings delete confirm) never showed it — the cost scales with dialog area. Do not re-add zoom utilities to DialogContent or any large dialog/popover; opacity-only animation stays on the GPU compositor. If a dialog still janks, the next suspect is the full-screen overlay compositing, not JS.

`StatsPage` (task 08-29-refactor-stats-page) is range-driven, not today-only. State: `{ kind: "today" | "week" | "custom" | "month", customFrom, customTo }` + `tagId` filter. All range presets (today/week/month) derive `from`/`to` client-side from `browserTz()` local dates (`todayIn(tz)` via `Intl.DateTimeFormat("en-CA", { timeZone })` — never `toISOString().slice(0, 10)`; week/month arithmetic happens on pure calendar labels via UTC-midnight `Date` objects, same手法 as `DateNav.tsx`) and call `api.statsRange(tz, from, to, tagId)`. Custom range uses a `Popover` + `react-day-picker` `mode="range"`; incomplete / `from > to` / >92-day ranges show a destructive hint and skip the request. Polling: only the `today` preset polls (5s); historical presets fetch once per parameter change. Cross-midnight roll: `todayIn(tz)` is cached in state (`todayKey`) and re-checked on each poll tick — updating it recomputes the query so a page left open past midnight rolls to the new day.

Layout (top → bottom), inside `PageContainer` `wide`: a toolbar row (range `Tabs` + custom-range `Popover`, tag filter dropdown `ml-auto`) → four module cards (`space-y-6`): total-logged card (`CardContent p-6`, `stats.totalLogged` label in `text-sm text-muted-foreground` + `font-mono text-3xl font-bold tabular-nums` number) → daily-trend card (`CardHeader` title + recharts `BarChart` in `ResponsiveContainer`, fixed `h-56`, bar fill `var(--primary)`, tooltip `formatDuration`) → category-share card (title + 独立/汇总 segmented toggle `ml-auto` in the header; recharts donut `PieChart` with innerRadius, `Cell` fill `paletteColor(color, name)`, center total; plus the horizontal bar list with a percentage column) → tag-breakdown card (pure-CSS bars; `tagId === null` renders `stats.noTag` with muted color; do NOT show a tags total — multi-tag entries count fully under each tag, so the sum can exceed `totalSeconds`). Empty state (`totalSeconds === 0`) shows `stats.emptyRange` guidance copy. Charts must take colors from CSS variables / `paletteColor` only (dual-theme safe). `recharts` is the only chart library allowed; the >500 kB bundle warning from it is accepted (code-splitting is out of scope).

Focus-outside guard (task 09-05-fix-menu-popover-focus, bug found in real browsers only): after a menu item's `onSelect`, the closing menu's teardown steals focus back (`MenuItem` `onPointerLeave` → `onItemLeave` → menu-container focus, plus `onCloseAutoFocus` → `⋯` button); since the popover uses `PopoverAnchor virtualRef` instead of `PopoverTrigger`, Radix's `targetIsTrigger` exemption never fires and the fresh popover would dismiss on that focus-outside instantly. Fix contract: both 添加子项/编辑 `onSelect`s stamp `popoverOpenedAtRef.current = Date.now()` right after `setPopoverTarget`, and both `PopoverContent`s pass `onFocusOutside` that `preventDefault()`s any focus-outside within ~300ms of open. Pointer-down-outside and Escape dismissal are NOT intercepted — only the focus-outside path has the grace window.

`ConfirmDialog` (`web/src/components/ConfirmDialog.tsx`, task 08-31-delete-dialog-confirm): the shared destructive-confirm primitive over `ui/dialog` — props `{ open, onOpenChange, title, description, confirmText, cancelText, onConfirm, pending?, destructive? }`. Purely presentational: no `api` import and no `t()` inside — callers translate (and interpolate, e.g. cascade counts) and pass plain strings; `pending` disables both buttons (double-submit guard); callers gate `onOpenChange(false)` on their in-flight flag so the dialog cannot be dismissed mid-request. Used by `EntryEditor` (entry delete), `HierarchicalListCard` (category/tag delete), and `TokensPage` (token revoke, task fix/token-revoke-confirm — previously an inline two-step confirm). It renders fine nested inside the Timeline `Popover` (Radix Dialog portals to body); after a successful delete `onSaved()` closes the popover and unmounts both — Radix effect cleanup restores body pointer-events. Entry/category/tag deletes and token revokes are dialog-confirmed; Goals keeps its inline two-click confirm (deliberately out of scope for 08-31-delete-dialog-confirm).

## Copy and controls

- UI copy is i18n-ized: all strings come from `t()` keys in `web/src/i18n/locales/` (zh default, en). Placeholders too (`timer.placeholder`, `timer.selectCategory`). Never hardcode UI copy in components.
- Buttons: `type="button"` unless they submit a form (`AuthPage`).
- Icons: Lucide only (`Timer`, `ChartNoAxesColumn`, `Tags`, `Tag`, `LogOut`, `Play`, `Square`).
- Category/tag colors resolve via `paletteColor(color, fallbackName)` in `format.ts` (stored palette index first, hash fallback) — see [Design Tokens](./design-tokens.md) for the fixed-at-creation contract.

## Anti-patterns

- Do not put category totals on the timer page.
- Do not add React Router; page state is `PageId` in `App`.
- Do not stop the timer on `beforeunload` — R7 says the timer survives browser close.
- `ui/card` is the single source of card styling — do not hand-assemble `border` + `rounded-*` + `shadow-*` on page-level divs.
- Keep cards light: no large shadows, no high-contrast elevated/floating cards, radius stays `rounded-lg`.
- Do not add a page-level `<h1>` — page titles render in the Shell top bar via the `header` prop.
- Do not mix another icon set or CSS framework on top of Tailwind + shadcn.
- Do not invent a bottom tab bar; mobile uses the sidebar drawer.
